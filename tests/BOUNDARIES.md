# 输入边界与错误分类验收

实际平台为 Windows amd64 / Chrome。文件系统名称限制由实际调用结果判定，没有以统一 UTF-8 字节上限截断或改写文件名。

| 约束 | 实际证据 |
| --- | --- |
| Markdown 1 MiB UTF-8 | 存储测试保存并原样读取精确 1 MiB 的中文正文；多一个字节或无效 UTF-8 均不发布笔记和快照。HTTP 超限正文返回明确输入错误。 |
| 上传 50 MiB | HTTP 精确上限的普通附件上传成功，下载字节逐一相等；超限一个字节返回 413 且不发布资源。 |
| CRDT 16 MiB | 浏览器发送解码后超限的更新，收到明确大小错误；合法删除历史增量各自低于上限、合并后越界时，房间拒绝，权威快照字节和修订不变，没有成功确认。 |
| WS JSON 24 MiB | 真实浏览器发送精确大小的合法 join JSON（含尾随空白）被接收；多一个字节关闭码为 1009，已保存修订不变。 |
| 每文件 16 连接 | 第 17 个连接收到 room_full；关闭一个连接后名额可再次使用。 |
| 图片像素 | PNG/JPEG/GIF/WebP 实际解码与命名测试通过；声明超过 6400 万像素的 PNG 在分配巨大像素缓冲和发布前拒绝。 |

## 修正的文件名问题

原先，300 字符名称在 Windows 文件系统返回原生名称拒绝时，会走内部错误并停止服务。现在该类入口拒绝返回 400 / invalid_filename，服务和已有编辑会话继续可用。

检查覆盖笔记、附件，以及笔记名本身可容纳但追加 `.json` 后无法存储的恢复状态名。派生恢复路径在写入前预检，不发布无效笔记或状态，也不为它们换名。Windows 原生接受的 100 个汉字文件名（超过 255 个 UTF-8 字节）仍按原名创建和打开。

## 保留 I/O 错误的优先级

名称验证与实际持久化失败分开处理。原子保存及资源发布中的非冲突 I/O 错误带有存储错误标记，即使底层原因是“路径不存在”等通常可作为输入错误的值，也不会误报为普通 404。

HTTP 分类检查每个被包装或合并的原因。冲突、名称错误或不存在错误一旦同时伴随关闭/清理失败，仍返回内部错误并通知致命退出路径。普通的独立名称、冲突和不存在输入继续返回相应 400/409/404。

测试覆盖真实文件系统拒绝后的无发布、运行中服务继续可用、合法中文名称，以及混合错误不能掩盖 I/O 失败。此记录不声称穷尽所有任意字节输入或所有文件系统的行为；Linux/macOS 实机结果仍待补齐。
