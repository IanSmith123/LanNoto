# 持久化故障与真实进程中断验收

实际运行平台：Windows amd64。`npm --prefix web test -- --project=faults` 会单独构建带 `lannoto_fault_test` 标签的服务，在独立工作区中运行真实浏览器与服务进程。生产构建不使用此标签。

## 普通构建的隔离

- 普通版本只保留可内联移除的空检查点，不读取故障环境变量或控制文件，没有故障 CLI 参数。
- 测试检查普通可执行文件不含 `LANNOTO_TEST_FAULT_DIR` 控制标记。
- 把故障环境变量和控制文件交给普通程序，实际编辑仍可正常保存。

## Write 与 Sync 错误注入

测试构建在指定文件的写入或同步调用边界返回受控错误，沿用与实际 Write/Sync 错误相同的处理分支，验证错误传播，不声称模拟了真实磁盘硬件损坏。真实服务必须退出码为 1；正式快照与原 Markdown 字节不变，页面不显示已保存。其他测试已通过真实目录替换失败和 Windows 文件占用验证原子替换错误。

## 两个真实落盘边界

检查点只在文件已实际替换并完成相应目录同步之后发出信号，不伪造快照或正文。控制进程先读取真实磁盘状态，再终止整个服务进程：

1. 首个投影快照已替换：快照含新正文与目标修订，但 diskHash 仍是旧 Markdown 摘要；原 Markdown 字节尚未变化。
2. Markdown 已替换：磁盘正文已是新正文；快照仍保留旧 diskHash，最终摘要提交尚未发生。

两种情况都检查页面未确认已保存。随后启动不带标签的普通服务，重新登录，验证新正文恢复一次、修订号不额外推进，快照正文等于实际文件，diskHash 等于实际 SHA256。已有 process 测试另行覆盖 CRDT 快照领先于 Markdown、真实快照替换失败及真实 Markdown 占用失败。

这证明进程终止后的恢复行为，不等同于跨系统突然断电测试。Linux/macOS 的实际文件系统及浏览器运行仍未验收。

故障构建使用的检查点信号位于测试工作区的 `.lannoto/test-fault/`，等待最多 20 秒，测试结束会终止其服务进程。测试二进制保存在忽略的构建目录，不作为正式发布程序。
