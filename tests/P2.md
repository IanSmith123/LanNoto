# 上传、导出与打印验证

验证平台：Windows amd64、Google Chrome、Pandoc 3.8.3、Go 1.26.10。

## 已验证

浏览器与真实进程回归包含字体失败、编辑空行导出、纸张切换和长页上限、已有仓库无 Git、侧栏协作目录等专项。2026-11-07 新增粘贴原名与冲突选择、空段落同步及选区保留、Pandoc 按需提示和纯笔记 ZIP。最新测试数量见 [源码检查记录](SOURCE_REVIEW.md)。固定样本的原生 PDF 公式、空白页和浅色矩形问题现已修复，实际范围见 [打印验收](PRINT.md)。

- 文件选择保留中文、空格和原名；PNG 原始字节完整，普通附件使用链接。
- 侧栏目录浏览器专项：保存/预览/上传/导出/打印均位于侧栏，正文容器从页面顶部 16 px 开始；H1–H5 层级、跨级标题、H6 排除、子目录折叠、远端标题更新及折叠状态保留、点击正文滚动均通过。目录不包含协作光标标签，单独折叠/展开不增加服务修订。桌面与 390 px 窄屏均有截图，窄屏页面没有横向溢出；截图存于忽略的 tests/artifacts/sidebar-outline*.png。
- 按用户后续反馈重排侧栏：工作区使用常驻 section，显示名称及新建输入无需展开；文件高亮当前路径，三种导出按钮同排且高度统一为 32 px，取消导出单独整行，退出登录位于底部。目录专项增加这些布局断言；文件创建回归直接填写新笔记，无折叠步骤。最终构建的 app 与 features 两组共 21 项回归通过。
- PNG/JPEG/GIF/WebP 均通过实际解码、原名与字节保留、截图真实扩展名测试；像素超限声明拒绝且不发布资源。WebP 使用自行生成的 8×6 测试色块，不增加运行时编码器。
- 浏览器合成粘贴事件先询问来源，保留原名、截图时间命名和取消均有测试；一次操作只上传一次。
- 另行通过真实系统剪贴板像素及 Ctrl+V 验证局域网 HTTP 页面，详见 [原生输入验收](NATIVE_INPUT.md)，不把此结果扩大为文件管理器文件剪贴板通过。
- 拖放 SVG 使用附件下载；同名返回 409，路径穿越和伪截图拒绝，未登录不能读取附件。
- Markdown 下载内容和文件名正确；Word 使用真实 Pandoc 转换，检查 DOCX ZIP 内中文、表格、代码、公式和本地图片。
- Pandoc AST 拒绝外部图片、路径穿越、data/file URI、缺失图片及原始 HTML/XML；并发上限和取消由后端测试覆盖。2026-11-07 移除裸 HTML 换行标签的开发兼容分支，标准 Markdown 换行仍可导出。
- 2026-11-03 的裸 `<br>` 转换方案已被替代：编辑器直接输出 Markdown 空白，2026-11-07 删除导出兼容转换。浏览器验证连续回车后下载 Word 成功，导出前后的 Markdown 字节一致；Go 验证标准 Markdown 硬换行和代码中的字面 HTML 可正常导出，原始 HTML/XML 拒绝。
- 导出要求修订已完成 Markdown 投影；过期修订返回 409，不提供服务端 PDF 接口。
- 打印使用独立只读官方 Crepe，无额外协作连接；打开后其他成员继续编辑，不改变打印快照；关闭后返回最新编辑内容。
- 打印图片加载失败会禁用打印并显示错误；图片和字体准备完成后才允许打印。
- 字体失败专项让打印正文实际使用随程序嵌入的 KaTeX 字体，通过浏览器路由阻断该字体的真实网络请求，确认 FontFace 状态为 error、打印禁用并显示字体失败；关闭预览后继续编辑并保存成功。该专项样式仅在测试页注入，不改变产品字体选择。
- 四个独立浏览器会话对 66,977 字节笔记连续编辑 10 轮，每轮四人同时写入。Windows 本机测得各轮全部标记可见为 69–134 ms，全部显示已保存为 380–886 ms。包含浏览器自动化与断言耗时，属于本机小样本，不代表网络部署的分位延迟。测试将逐轮数据写入忽略的 `tests/artifacts/performance.json`。
- Linux amd64/arm64、Windows amd64、macOS amd64/arm64 均已交叉编译通过；实际运行测试目前只有 Windows amd64。
- 独立测试转换进程注入退出码 17 和 stderr、两个任务并发满额、页面取消及真实 60 秒超时：页面分别显示失败、忙碌、取消、超时，取消/超时后子进程确实退出，协作编辑仍可继续。真实 DOCX 内容由另一个使用正式 Pandoc 的测试验证，故障夹具不用于证明转换正确性。
- 五个平台发布压缩包已由 `scripts/release.mjs` 生成，内含完整许可证与文档，SHA256 清单已复核。解压后的 Windows 包在独立 CWD、PATH 仅保留 Windows System32（无 Node/npm/Git）、显式指定真实 Pandoc 时成功启动，提供嵌入页面、完成登录并发现已有中文笔记。这不代表其他平台实机验证。
- 另行通过已有 Git 仓库专项：独立夹具仓库只提交一个哨兵文件，服务进程的 PATH 找不到 Git，显式提供 Pandoc 后完成中文/emoji 编辑保存及重启恢复；停止服务后逐文件 SHA256 核实整个 `.git` 内容和哨兵文件未改变。测试不把笔记加入任何 Git 提交。
- 真实浏览器的 16 连接边界：编辑器占一个连接，另外 15 个成功；第 17 个明确返回 `room_full`，关闭一个连接后可以加入替补。
- 畸形 JSON、未知 join 字段、二进制帧、跨源写入均明确拒绝，服务继续可用；超过 50 MiB 的上传不发布资源，超过 1 MiB 的新建正文返回明确正文错误且不创建文件。
- 后续补齐精确上传/正文边界、CRDT 输入及合法增量合并超限、24 MiB WS 包含边界与多一字节关闭，详见 [输入边界验收](BOUNDARIES.md)。
- 浏览器页面阻断全部外部 HTTP 请求时，正式嵌入的编辑器、公式字体、本地图片与打印快照均准备成功，观察到的外部页面请求为零。此项验证不等同于修改主机网络或真实局域网剪贴板验收。

## 验证边界

浏览器合成粘贴/拖放事件不能证明操作系统剪贴板来源，也未操作桌面或文件管理器。真实 Chrome 打印窗口已验证取消并继续编辑，亦已通过隔离 PDF 目标生成实际文件。固定验收样本通过不代表所有浏览器及任意文档的排版保证；详见 [真实打印验收](PRINT.md) 和 [验收核对](ACCEPTANCE.md)。关闭或取消打印不会显示已保存 PDF。
