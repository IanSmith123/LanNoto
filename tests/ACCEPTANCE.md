## 2026-11-06 未关闭缺陷修复

关闭固定样本中的 PDF 离屏公式、分页空白与尾部灰块问题，证据和适配方式见 PRINT.md。所见即所得通过公开 paragraphSchema 配置将空段落序列化为 Markdown 空白，不再生成 HTML 占位，保留用户输入的临时空段落供继续编辑。连续回车后实际下载 Markdown 无 br 标签、含后续正文，Word 下载成功且导出前后原文不变。

当前未关闭：Windows 偶发原子替换拒绝访问。本轮完整浏览器运行在 boundary 离线资源场景再次复现（工作区 p1-hlrNAw），其后两项测试因服务已退出而失败。独立 20 轮、每轮 100 次、8 个并发读取者的压力测试未复现；此前持有者仍未确定。不能用本轮通过推断问题消失，没有增加忽略错误、复制覆盖或重试。原生输入与第二台设备、Linux/macOS 实机等缺乏证据的项目继续保留为未验收，不将它们称作已确认缺陷。


为捕获后续根因，Windows 替换失败增加系统 Restart Manager 只读查询，记录目标和临时文件的占用进程；从不调用关闭或重启进程接口。无法查询或系统未报告占用者时明确记录该状态，原始 I/O 错误仍保留并致命退出。单元测试实际持有一个禁止删除共享的文件，验证原子替换失败且记录当前占用进程 PID。诊断版针对原失败场景连续运行 40 次通过，不能据此关闭偶发缺陷。API 依据：[Microsoft Restart Manager](https://learn.microsoft.com/en-us/windows/win32/api/_rstmgr/)。


另发现初始化或仅 CRDT 状态改变时，即使目标 Markdown 已在磁盘上，也会多余执行一次替换。WriteMarkdown 现先校验实际磁盘摘要，再逐字比较，相同则完成投影而不替换文件。Windows 回归测试持有禁止删除共享的真实文件：相同内容可保存，过期摘要仍拒绝。此修改避免该类无意义替换冲突，不把它扩大为已定位所有偶发占用来源。真实正文变化时仍使用原子替换并严格传播失败。


已核对本次实际失败工作区 p1-hlrNAw：初始化 revision=1、markdownRevision=1，快照 Markdown 与原磁盘逐字相等，diskHash 也等于磁盘摘要。因此跳过相同正文的替换直接消除了此次已观察到的失败路径；这与泛化假定“任何拒绝访问都可忽略”不同。仍不宣称已识别文件占用者，也不保证外部程序禁止共享时能替换真正改变的文件。

最终验证：62 项浏览器回归全部通过，含离屏公式持续渲染、公式语法错误后修复重试、普通空段落无 HTML、多人协作、导出、历史及持久化故障。Go 全量、race 及 lannoto_fault_test 标签测试通过。五平台交叉编译更新；实机范围仍为 Windows amd64。

## 2026-11-07 刷新连接生命周期修复

用户点击“刷新文件列表”可复现 `Sending on a disconnected socket`：旧连接关闭后，编辑器销毁会触发 awareness 的本地状态移除；原在线标记尚未清理，回调向已关闭的 WebSocket 发送并进入全局不可恢复错误。

销毁现先置为关闭和离线，随后只读、关闭连接、等待消息队列并销毁编辑器。关闭后不再广播在线状态或更新旧页面成员。发送时发现浏览器连接已关闭但尚未收到 close 事件，按正常断线处理，正文 pending 保留供重连重发。异步初始化恢复后重新检查原连接身份与状态，关闭期间排队的消息不再用于恢复旧连接；真实协议错误仍报错。

新增回归先在旧构建复现报错，再验证连续三次刷新文件列表、继续编辑保存、浏览器刷新后正文仍在且没有错误提示。原有断线重发、初始化确认丢失、双初始化者、协作撤销等回归继续验证。
